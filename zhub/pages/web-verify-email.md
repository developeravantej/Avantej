## 1. What It Does

**Purpose (user perspective):** Completes the email verification flow by consuming a one-time token from a verification email and then redirecting the user.

**Produces:** A centered card showing a loading spinner → success checkmark → redirect, or an error message with the failure reason.

**On success:** Shows "Email verified. Redirecting…" with a green checkmark, then after 1200ms navigates to `callbackURL` (defaults to `/login`).
**On failure / error states:**
- Missing token → "Missing verification token." error state immediately.
- API call fails (expired / invalid token) → "Email verification failed. The link may be expired or invalid."

---

## 2. How It Works

**Execution flow:**
```
VerifyEmailPage
  → useSearch({ from: "/verify-email" }) — reads token + callbackURL
  → useEffect: calls client.auth.verifyEmail({ token })
      → POST /rpc/auth/verifyEmail (oRPC)
          → Better-Auth verifyEmail handler
  → on success: setStatus("success") → setTimeout 1200ms → navigate(callbackURL)
  → on error: setStatus("error") + setErrorMessage
```

**Inputs:**
- `?token` (string, required) — verification token from email link
- `?callbackURL` (string, optional) — redirect destination after success; must be a relative path starting with `/` (not `//`); defaults to `/login`

**State management:** Local `useState` for `status` ("loading" | "success" | "error") and `errorMessage`.

**Outputs:** Status card with one of three states (loading spinner, success checkmark, error with message).

**Side effects:**
- Calls Better-Auth's verify-email API which marks the user's email as verified in the auth DB.
- Navigates to `callbackURL` after successful verification.

## 6. Notes

- The `callbackURL` validation in `validateSearch` strips any value that starts with `//` or is not relative — this prevents open-redirect attacks via the email link.
- The 1200ms delay before redirect is intentional UX to let the user see the "verified" confirmation before being sent away.
- A `cancelled` ref ensures the async effect does not update state after the component unmounts (e.g., if the user navigates away during the 1.2s delay).
- This page uses the oRPC `client` (not the legacy REST `apiClient`) — consistent with the rest of the authenticated app.
