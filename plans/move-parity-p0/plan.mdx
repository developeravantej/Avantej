### Objective

Close the money-correctness, back-office, and onboarding gaps that a live audit of the competitor product **MOVE OS** (`move-session-billing-staging.onrender.com`) surfaced against the Avantej tenant dashboard — and overshoot each one so Avantej is the stronger product, not a copy. MOVE OS is a single-region-per-tenant, multi-currency gym-billing OS; it is a useful **feature reference**, not an architecture model. Avantej already meets or beats it on Dashboard, Clients (Customer-360), Commission ledger, Users/RBAC, and Promotions. This program lands the seven pieces where MOVE is currently ahead or where Avantej is only partial.

**Done means:** a multi-country tenant sees correct per-currency money everywhere; the ten operational reports exist as row-level, exportable tables scoped by RBAC hierarchy; invoices carry a per-branch company/tax profile and gapless per-branch numbering; sessions auto-complete and settle coach pay after the cancel window without a human; commission months lock (auto + manual) and reject back-dated edits; and a tenant admin can self-serve CSV import (onboarding) and CSV export (portability) from the dashboard.

### The hard-to-reverse bets (decide now)

These are the choices that become expensive once data or callers depend on them. They are settled here; the few genuinely-open forks are in **Open Questions** at the bottom.

<Callout id="bet-currency" tone="decision">

**Currency is stamped on every money row at creation from the branch's currency, and the branch's currency is the single source of truth.** Currency columns already exist inconsistently today: `appointments.currency` defaults `"MYR"`, but `payments.currency` and `payouts.currency` default `"usd"` and `expenses.currency` defaults `"myr"`. Two money tables have **no** currency at all (`commission_splits`, `service_prices`). The bet: add `branch_details.currency` (seeded from the branch's `hierarchy_nodes` country node), make it authoritative, add currency to the two tables that lack it, and **correct** the wrong-default rows (not just NULLs) by backfilling from each row's branch. Then every summary `GROUP BY currency`. This is real schema work, not a one-column add — and WS2/WS3 money display depend on it, so WS1 ships first.

</Callout>

<Callout id="bet-sales-alloc" tone="decision">

**Dual sales allocation (Lead Originator vs Sales Rep) is modelled as two typed split rows, not two columns on the sale.** Avantej's `commission_splits.roleType` already carries `trainer | sales | marketing | referrer`. MOVE hardcodes exactly two 5% sales slots; Avantej keeps its N-configurable slot model and adds `lead_originator` + `sales_rep` to the role vocabulary. Note this **is** a shared-type change: `CommissionRoleType` is a closed union in `packages/types`, so every exhaustiveness switch on it must be updated. Small but real — not "no schema fork". Avantej stays more flexible than MOVE.

</Callout>

<Callout id="bet-numbering" tone="decision">

**Invoice/receipt numbers are `prefix + gapless per-branch sequence`, allocated transactionally from a counter row.** A `branch_number_sequences` row per (branch, docType) is incremented inside the same transaction that writes the invoice/receipt, so numbers never gap or collide under concurrency. The sequence is a `bigint` (no hard cap) zero-padded to a per-branch configurable display width, so there is no permanent 999,999 ceiling. The wire format `<prefix><padded-seq>` is customer-visible and permanent once invoices are issued — it is fixed here.

</Callout>

<Callout id="bet-payroll" tone="decision">

**A payroll period is a first-class row keyed to a commission-cycle window, with an enforced write-gate.** Rather than derive lock state ad hoc, introduce `payroll_periods` and reject any commission write dated into a `locked` period at the service layer. Windows come from the existing `commission_cycle_configs` resolver, so a tenant on a non-calendar cycle still locks correctly — MOVE only understands calendar months.

</Callout>

<Callout id="bet-import" tone="decision">

**Import idempotency is a crosswalk (external natural key → internal id), built on the existing ETL primitives — not a fresh insert path.** The developer xlsx ETL already has canonical DTOs, a crosswalk, and loaders for **Clients, Staff, Product, Location, Appointment only**. Packages, Payments, Payees, Service-categories, and Opening-balances have **no loader yet** — those are net-new and are the bulk of WS6's work. The dashboard importer wraps loaders behind an oRPC `importPreview` (per-row Zod validation) + `importCommit` (single transaction) so a re-run upserts instead of duplicating. CSV column headers (the downloadable templates) are the public contract and are versioned. A `data_import:manage` permission must be added to `seed-rbac.ts` + backfilled to existing tenants (same gap class as prior owner-permission fixes).

</Callout>

### WS1 — Multi-currency correctness (P0, foundational)

**Reuses:** the existing `currency` columns on `appointments` / `payments` / `payouts` / `expenses`; `liabilitySummary` / `liabilityByStaff` / `listCommissionLedger` in the commission service; the `hierarchy_nodes` country nodes (`type='country'` / `countryNodeId`). **Adds:** `branch_details.currency` as the source of truth, a `currency` column on the two money tables that lack it (`commission_splits`, `service_prices`), `GROUP BY currency` in every aggregate, a corrective backfill, and removal of hardcoded `"MYR"` in the UI.

Today the commission ledger, branch revenue (`TreeRow`, `NodeDetailPanel`), and package pricing all render assuming MYR, and the currency columns that do exist disagree (`payments`/`payouts` default `usd`). A tenant operating MY+TH+SG (exactly MOVE's shape) sees co-mingled, wrong grand totals. This is a correctness defect, not cosmetics.

<Code
  id="ws1-resolve"
  filename="packages/services/src/currency.service.ts"

  caption="Currency comes from the branch; the branch is seeded from its country node. New columns get NOT NULL; existing wrong-default rows are corrected, not just NULLs."
  code={"export async function resolveBranchCurrency(\n  tenantDb: TenantDb,\n  branchNodeId: string,\n): Promise<string> {\n  const branch = await tenantDb.query.branchDetails.findFirst({\n    where: eq(branchDetails.nodeId, branchNodeId),\n    columns: { currency: true },\n  });\n  if (branch?.currency) return branch.currency; // authoritative once set\n  // seed path: walk node -> country node -> currency map\n  const countryCode = await resolveCountryCode(tenantDb, branchNodeId);\n  return COUNTRY_CURRENCY[countryCode] ?? \"MYR\";\n}"}

<Callout id="ws1-risk" tone="risk">

Backfill has two edges, not one: (1) the **new** columns (`commission_splits.currency`, `service_prices.currency`) ship nullable → backfill from each row's branch → `NOT NULL`; (2) the **existing** columns carry wrong defaults (`payments`/`payouts` default `usd`) — the backfill must **overwrite** those to the branch currency, not skip them with a `WHERE currency IS NULL` guard. Idempotent SQL, verified with `bun verify:migrations` + `bun scripts/check-drift.ts` before rollout.

</Callout>

### WS2 — Reports suite: 10 operational reports (P0, largest surface)

**Reuses:** `getStaffPerformance` (as a *starting point* for Coach Productivity — it returns only `{staffId, appointmentCount, totalCommission}`, so tier / distinct clients / no-show% / credits-earned are net-new), `getRevenueSeries`, and the sales-order / invoice / credit-ledger schemas (the data already exists). **Adds:** a `reports/` router folder with a shared input contract, ten row-level query procedures, a Reports index with a custom date-range picker + tax-basis toggle, virtualized tables, and per-report CSV via the shared codec (WS7).

Avantej today has aggregate KPI tiles but none of MOVE's row-level reports. The data is present; this is mostly a surfacing job. Every report shares one input and is guarded by `accessibleNodeIds` — so a Branch Manager sees only their branches, which MOVE's flat "all branches" cannot do.

<Callout id="ws2-package-branch" tone="warning">

Two reports need a schema fix first: **Expiring Credits** and **Services Owed** read `package_instances`, which has **no branch column**, so they cannot be `accessibleNodeIds`-scoped as-is. Either add a `branch_id` to `package_instances` (backfilled from the originating sale) or join through the sale/order to the branch — decide in WS2, do it before those two reports. Also extend `listExpiring`'s hard-typed `within: 7 | 30` to include the 60-day window this report specifies.

</Callout>

### WS5 — Month-based payroll period lock (P0)

**Reuses:** `commission-cycle.service.ts` (`resolveCyclePolicy` / `deriveCycleBounds`), the `migrate-all-tenants` cron pattern. **Adds:** the `payroll_periods` entity, a grid UI, an auto-lock cron, and a write-gate in commission paths.

Avantej locks per-split/per-batch; MOVE locks a whole month with auto-lock + grace and blocks back-dated edits. Without a period gate, a correction can silently land in a settled month and change already-paid totals. The cycle resolver is **per-branch**, so a payroll period is keyed `(branch, window)` — a multi-branch tenant on differing cycles can't be collapsed to one org-wide period.

### WS7 — CSV export catalogue (P1, pulled forward)

**Reuses:** `runTenantExport`'s generic table enumeration (`Object.keys(tenantDb.query.*)`) as the dataset-discovery pattern. **Consolidates + adds:** there are three divergent CSV writers today — `apps/web/.../reports/export-csv.ts` (client, exported), and the **private** `escapeCsvField`/`rowToCsvLine` in `cancelled-sales.service.ts` plus a private writer in `scheduled-reports.service.ts`. WS6+WS7 extract one shared `packages/services/src/csv-codec.ts` (parse + serialize, FK-preserving) and migrate those callers onto it, then add a schema-driven ~25-dataset manifest, per-dataset exporters, an `exportAll` zip, and a tenant Export page.

Import and export are the two halves of data portability; shipping them together means the codec, the entity manifest, and the templates are authored once and shared. Today the only full dump is a super-admin JSON blob tied to tenant deletion — not tenant-facing, and its delivery is a `data:` URL (R2 upload is an explicit TODO in `runTenantExport`), so large-export delivery is net-new.

### Risks

<Callout id="risk-backfill" tone="risk">

**Currency backfill (WS1)** touches live money rows on every tenant. Follow the tenant-migration workflow strictly: idempotent SQL, add nullable → backfill from branch country → `NOT NULL`, commit the regenerated `*.generated.ts`, and verify with `bun verify:migrations` + `bun scripts/check-drift.ts` before rollout.

</Callout>

<Callout id="risk-bulk" tone="risk">

**Bulk/auto appointment paths (WS4)** must not bypass `updateAppointment`. A raw `UPDATE appointments SET status='completed'` would skip credit debit and commission and silently break payouts — the exact domain rule CLAUDE.md protects. Every bulk/cron transition loops the existing mutation.

</Callout>

<Callout id="risk-import" tone="warning">

**Import commit (WS6)** runs untrusted CSV against real inserts. Enforce `requirePermissionOrpc` + `assertOrgContextMatch`, cap row counts per job, run inside one transaction, and rely on the crosswalk so a double-submit upserts rather than duplicates.

</Callout>
